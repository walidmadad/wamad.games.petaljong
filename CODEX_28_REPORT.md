# CODEX 28 — Victory-only timed test interstitials

A. Executive summary: implemented one interstitial opportunity per newly played victory after at least 180,000 ms of active gameplay. Startup, Play, Home, reconnection and Next Level contain no presentation trigger. Only official Google test IDs are configured. Nothing was published, pushed, uninstalled or cleared.

B. Architecture audit: inspected MainActivity, LevelNavigation, ProgressController/GameSession, GameStore, ProgressRepository, RewardedAdManager, ConnectivityMonitor, manifest, Gradle configuration, existing JVM/instrumentation tests, CODEX 27 report and `.tilebloom-git` history. Existing SDK is legacy `play-services-ads:25.5.0`, with UMP 4.0.0. Existing process-owned rewarded manager uses weak Activity references and AdReward/AdPresentation for persistent, duplicate-protected reward grants. CODEX 27's offline composition and completed-entry finalization remain. The pre-existing privacy-options refresh in RewardedAdManager was preserved.

C. InterstitialAdManager: dedicated legacy InterstitialAd.load/FullScreenContentCallback wrapper. Application-context asynchronous loading, one cache, one-hour expiry, 30-second load-failure backoff, no automatic retry loop and no retained Activity. Availability is checked before scheduling the victory transition and again at display. Release builds retain empty ad units and the existing release-build block. Debug interstitial unit is `ca-app-pub-3940256099942544/1033173712`; rewarded unit remains `ca-app-pub-3940256099942544/5224354917`.

D. Frequency: Android-independent InterstitialFrequencyPolicy saturates at 180,000 ms. It accumulates monotonic eligible intervals, consumes each forward-only level victory identity once, and resets only for a successful full-screen shown callback. Unavailable inventory or a pre-display failure leaves accumulated time intact for a future victory.

E. Active timing: elapsedRealtime snapshots at lifecycle, focus, navigation, connection, game-status, consent and ad transitions. ActiveGameplayConditions excludes background/unfocused, home, terminal, loading, offline, full-screen ad, consent and modal-dialog states. No ticking timer or per-frame work. Frequency writes occur at relevant boundaries, not once per second.

F. Victory flow: board-selection callback updates the normal completion UI and stops timing, verifies WON, verifies durable victory persistence, consumes and durably records the opportunity. If already loaded and eligible, a 350-ms transition allows the existing 180-ms match feedback and completion confirmation to finish. Next Level is temporarily disabled only for that pending transition/full-screen presentation. Missing ads skip immediately. The delayed callback rechecks level, route, foreground, focus, network and full-screen exclusion. Pause cancels the pending transition. Existing +1 progression logic is retained.

G. Dismissal/failure: cached ads are removed before show. FullScreenAdLifecycle ignores duplicate/late shown and terminal callbacks. Dismissal and failures release the shared presentation gate and restore normal victory controls through the current Activity listener. Interstitial code never mutates board, progression or credits. No queued presentation or inventory spinner exists.

H. Rewarded interaction: existing voluntary Watch Ad flow, purpose selection, earned callback, duplicate reward guard and persistent balances remain. The only integration additions are consent/timing notifications, validated-network loading/show checks, shared full-screen exclusion and a shown callback resetting interstitial frequency even when no reward is earned. Failed requests/shows do not reset it.

I. Consent/connectivity: requests require existing SDK initialization, UMP canRequestAds(), no active consent operation and validated default connectivity. No additional SDK or consent UI. Consent unavailability does not prevent gameplay. Reconnection only prepares inventory and resumes eligible timing; it never presents an ad. Offline screen and board/credit preservation are unchanged.

J. Persistence/lifecycle: separate `ad_frequency` preferences hold bounded active duration, last consumed level and a presentation-in-flight marker. No monotonic timestamp is persisted. Interrupted full-screen presentations restore conservatively with zero accumulated time. Presentation acquisition requires durable marker persistence; a victory is skipped if its opportunity cannot be durably recorded. Process-owned SDK state and current-Activity notifications survive recreation; listeners are detached on destruction. Test storage is debug-only and separate from player preferences.

K. Duplicate prevention: deterministic forward-only level ID is the opportunity identity; recorded before asynchronous presentation. Restored games do not execute the board-selection victory callback. Recreation, fresh completed-entry finalization, duplicate SDK callbacks and stale delayed transitions cannot authorize an old victory again.
