# CODEX 57 — startup connectivity

A–B. Root cause: MainActivity initialized `online = false` and rendered the Home offline page whenever `!online`, before the worker's first connectivity result. This bypassed the old ConnectionState panel debounce. Resume also reset online to false. The monitor represented connectivity with two booleans and re-queried synchronous capabilities from every callback, including onAvailable, discarding onCapabilitiesChanged's supplied capabilities.

C–D. ConnectivityStatus now explicitly distinguishes CHECKING, ONLINE and OFFLINE. Activity starts and returns from stop in CHECKING. The initial default-network snapshot can establish ONLINE immediately. Missing validation remains CHECKING for at most 1,500 ms per verification attempt, then becomes OFFLINE. This gives asynchronous Android validation a brief opportunity to arrive without imposing any delay on confirmed Internet. The timeout and handover window are constructor parameters in the pure reducer; tests supply timestamps directly. CHECKING uses the existing green Home background and Petaljong title, with error message, Retry, Settings and offline privacy actions hidden.

E. All monitor state, snapshot reads, callback events and deadlines run on one HandlerThread. Callback registration precedes the initial snapshot on that same handler; subsequent queued events supersede it. Snapshot revision tokens reject obsolete observations. Generation guards discard callbacks and main-thread publications from stopped observations. Network identity filters prevent loss of the previous default network from replacing the new default's state. onAvailable never establishes validation or synchronously queries capabilities; onCapabilitiesChanged requires both INTERNET and VALIDATED from its supplied capabilities. Callback registration is idempotent; stop unregisters and cancels the timer; destroy quits the worker. Only application context is retained by the platform manager.

F–G. Loss of validation immediately blocks input and starts a non-extending 600 ms CHECKING window. Recovery cancels the pending offline transition immediately. Sustained loss presents the existing dedicated offline UI. Retry starts a bounded verification using the same registered observer; automatic recovery requires no Retry. ACCESS_NETWORK_STATE remains present. Wi-Fi transport alone and captive portals do not establish ONLINE.

H–I. No gameplay, progression, save codec, puzzle generation, wallet, move history, mystery lifecycle, UMP, ad frequency/cooldown, translation or artwork code was changed. Existing lifecycle persistence and input guards remain. While OFFLINE the retained gameplay view is hidden, preventing the board and level label from showing beneath the offline shade; recovery reveals the same view and puzzle. Connectivity is independent of consent and ad inventory. Existing fake-source Android connectivity tests preserve snapshots and credits and exercise privacy with no ad inventory; their event API was updated.
